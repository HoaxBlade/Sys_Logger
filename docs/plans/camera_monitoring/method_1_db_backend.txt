METHOD 1: THE DATABASE & API FOUNDATION (THE ADDRESS BOOK)
================================================================================

1. LOGIC OVERVIEW
-----------------
The system needs a "memory" of where the central cameras are located. We won't 
install software on the cameras, so we store their local RTSP URLs and link 
each camera to a "Host Node" (an existing PC in the lab) that is responsible 
for fetching the video.

2. DATABASE CHANGES (PostgreSQL)
--------------------------------
FILE: [Direct SQL Execution]
NEW TABLE: `cameras`

Columns:
- id: SERIAL PRIMARY KEY
- name: VARCHAR(255) (e.g., "Lab North Entrance")
- rtsp_url: TEXT (e.g., "rtsp://admin:pass@192.168.1.50/stream")
- organization_id: INTEGER (Link to the Org)
- host_unit_id: VARCHAR(50) (The ID of the PC node that will relay the video)
- status: VARCHAR(20) (Default: 'OFFLINE')
- created_at: TIMESTAMP

3. BACKEND FILE MODIFICATIONS
-----------------------------
FILE: `backend/sys_logger.py`

A. Add new endpoints for Camera Management:
   
   - GET `/api/cameras`:
     ```python
     @app.route('/api/cameras', methods=['GET'])
     @token_required
     def get_cameras(current_user):
         conn = get_db_connection()
         cur = conn.cursor(cursor_factory=RealDictCursor)
         cur.execute("SELECT * FROM cameras WHERE organization_id = %s", (current_user['org_id'],))
         cameras = cur.fetchall()
         cur.close()
         conn.close()
         return jsonify(cameras)
     ```

   - POST `/api/cameras`:
     ```python
     @app.route('/api/cameras', methods=['POST'])
     @token_required
     def add_camera(current_user):
         data = request.get_json()
         conn = get_db_connection()
         cur = conn.cursor()
         cur.execute("""
             INSERT INTO cameras (name, rtsp_url, organization_id, host_unit_id)
             VALUES (%s, %s, %s, %s)
         """, (data['name'], data['rtsp_url'], current_user['org_id'], data['host_unit_id']))
         conn.commit()
         cur.close()
         conn.close()
         return jsonify({'message': 'Camera added successfully'})
     ```

B. Logic for "Host Node" Mapping:
   - When a camera is added, the backend must verify that the `host_unit_id` 
     belongs to the same Organization. This prevents one lab from accidentally 
     using another lab's PC as a bridge.

4. SQL SCHEMA PIECE
------------------
```sql
CREATE TABLE cameras (
    id SERIAL PRIMARY KEY,
    name VARCHAR(255) NOT NULL,
    rtsp_url TEXT NOT NULL,
    organization_id INTEGER REFERENCES organizations(id),
    host_unit_id VARCHAR(50) NOT NULL,
    status VARCHAR(20) DEFAULT 'OFFLINE',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

5. CHALLENGES TO ADDRESS
------------------------
- RTSP URL Security: We must ensure these URLs are only sent to the Host Node,
  not leaked to unauthorized users.
- Validation: The RTSP URL must be checked for basic format (starts with rtsp://).
